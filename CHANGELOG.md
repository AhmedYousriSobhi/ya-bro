## [Unreleased]

### Added
- Struggle replay eval (#24, ADR-0010, ADR-0016): `broctl eval struggle [-v] [--sensitivity N] [--sweep]` replays `evals/struggle/` (62 labelled event streams: 54 scripted, 8 recorded from a real bash with the hook) through the detector on a fake clock and scores precision, recall, time to offer, false offers per hour of calm and the back-off rules, with the ADR's gates (exit 1 below them). Default sensitivity: precision 97%, recall 74%, median 20 s, 0.31 false offers per hour. Tests show that breaking the back-off, or making the detector jumpy or deaf, fails the eval. `scripts/dev/make_struggle_corpus.py` builds the scripted set; `python -m tests.record_struggle` records the real-bash set.
- Struggle detector (#9, ADR-0010): `ya_bro.struggle` takes content-free observations and offers help at a breakpoint when a decaying score passes the threshold, with the whole back-off policy (one pending offer, 2 min cooldown, 3 an hour and 10 a day, a "no" silences that signal until the context changes, two in a row silence the app for 30 min, three in a week halve the weight, "not for this app", opt-in per app, sensitivity 1 to 4). Sources built: failing commands from the shell hook and idle from GNOME's IdleMonitor (`StruggleHost`); packs tune it with `signals.toml` (workbench ships one). `broctl struggle status|on|off|enable|disable|sensitivity|watch`. Off for every app until you enable it. Tested with real bash plus the real spool and with real Mutter idle in the isolated shell. The AT-SPI sources (menus, dialogs, undo), the offer bubble and the learned gate are not built.
- Shell hook and terminal reading (#21, ADR-0021, ADR-0025): `shell/ya-bro.bash` records, for commands you allowed with `broctl targets allow --command`, only the name, exit code, duration and tty when each finishes (no arguments, no output; nothing for other commands, nothing at all while Ya-Bro is not running); `ya_bro.shell_spool` is core's side (private runtime dir, allowlist file, validated reads); `ya_bro.terminal` reads a VTE terminal's text over AT-SPI after you accept help (redacted, bounded) and finds the pack's fix-it for a `CODE: message | fix: COMMAND` line; `broctl hook install|uninstall|print|status` (edits `~/.bashrc` only after a yes) and `broctl shell watch`. Bash only. Tested in a real interactive bash (100 commands, under 5 ms per command, existing DEBUG trap and `PROMPT_COMMAND` kept) and on a real VTE terminal in the isolated shell.
- Pointing eval harness (#19, ADR-0007, ADR-0016): `ya_bro.grounding` turns an AT-SPI element list into a pointing with a confidence tier (high: same name after normalising and a 0.3 margin; medium: close or tied, shown with a hedge, "I think it's this one"; none), skips a ring whose centre is outside the focused window (ADR-0004), and the step loop now uses it (it used to take the first match). `AtspiPerception.find` returns each element's own name. `broctl eval pointing [-v] [--dir]` scores labelled snapshots in `evals/pointing/` (pointed-correct against the 80% gate, confidently-wrong against 2%, blocking release above 5%, medium precision, latency per tier, misses by kind, locale and app; exit 1 below the gate). Ships 300 **synthetic** cases (6 made-up apps, English and Arabic; `scripts/dev/make_pointing_corpus.py`) and 219 cases from **recorded real trees** of GNOME Calculator, Files and Settings (`tests/fixtures/shell_pointing.py`). Real-app checks in the isolated headless shell: all 10 Calculator digit keys pointed at by name and clicked in the ring type that digit, 7 × 6 = 42 by pointing at each key, Settings and Files rows open their page when clicked.
- Local policy engine and redaction (#20, ADR-0014 §4): `LocalPolicy` takes the highest of the step's risk, the pack's risk for that element and local heuristics (a bilingual whole-word deny-list on the element name, destructive-command patterns, password fields and pack-marked secrets). Show-me marks R3 steps as the user's own click; Do-it (still off) shows R3 and never acts, confirms R2, and never touches a secret field. Packs declare element risk and secrets with `[[element]]` (ADR-0027). `ya_bro.redact` replaces private keys, JWTs, AWS, GitHub, Slack and API keys, bearer tokens, `password=`-style values and URL passwords with `[redacted:kind]`; the bro's echoed screen text is redacted before it is cut. Tests: 177 element names (EN and AR) in both modes (354 decisions) and 50 injected texts that change no decision.
- App knowledge pack format v1 and loader (#8, ADR-0027): `packs/<id>/pack.toml` + `knowledge.md` + `tasks/*.toml`, exact app matchers, validated at load, broken packs skipped; `broctl pack list|check`; first pack `packs/gnome-calculator`.
- Workbench pack (#22): `packs/workbench` for `benchctl` (vocabulary, rules and common mistakes from AGENTS.md, four terminal tasks, 32 error-code explanations in `fixits.toml`). Pack format gained `fixits.toml` (ADR-0027); a suggested command must be one of the pack's own.

## [0.1.0] - 2026-11-22
First tagged release (pre-alpha): the scripted Show-me loop on GNOME Wayland, with hand-written plans. No LLM brain, voice or Do-it mode yet.

### Added
- Fixed the ring tinting the window interior (its glow filled the box; now a plain 4 px border, pixel-tested) and `broctl point` now draws only on a focused allowed window and tells you which window to click otherwise (#59).
- `broctl load`: loads the Ya-Bro extension into the running Shell without logging out. It copies a one-line snippet to the clipboard and walks through Alt+F2, `lg`, paste; verified in the isolated headless shell with injected keys (#57).
- Measured that a locally installed Shell extension cannot be loaded without a Shell restart (ADR-0023 §9).
- `broctl point` draws the Ya-Bro ring and a bubble on your allowed app's window and follows it (Stop button or Super+Shift+Esc hides it); `broctl scope watch` prints allowed windows entering and leaving scope. Both stand in for core until it exists, run under the system python3 with PyGObject, and were tested in the isolated headless shell only (#53).
- `broctl setup` shows a searchable list of installed apps (type a word, pick a number) instead of asking for a raw app id; it stores the window class when the app has one (#51).
- Spike S8 (#47): the Shell extension can scope a window by a secret title token pushed by core (`Bridge1.SetScopeTokens`, core only, memory only; the window leaves scope when its title changes), and windows re-evaluate when `allowed-apps` changes. Verified with a stand-in window and a real browser (Chrome for Testing; `pytest -m gnome_measure`). Findings in `docs/research/spikes/S8-active-tab-scope.md`.
- README demo GIF, narrated (#82, #84): native resolution with one shared 256-colour palette (86 KB, 606 x 798), a narrator caption track, a title card, and the funny parts: the wrong-key tease, **Why?** explaining the mistake, the forgiveness; `scripts/dev/record_demo.py` produces it.
- Repository polish (#80): professional README (badges, demo, status table, quick start, safety, command table), a step-by-step [user guide](docs/guides/getting-started.md), MIT `LICENSE` (the maintainer chose MIT only; ADR-0020 updated, `pyproject.toml` metadata), GitHub topics and description, a neutral [how-it-works diagram](docs/assets/how-it-works.svg) in place of the mascot concept sketch (removed), and a Show-me GIF recorded without the placeholder avatar (`ShowStep` takes `avatar = false`).
- ADR-0026 records the Show-me step loop decisions (#78); README status, ADR-0024 command list, SPEC (as-built loop), milestone table and the CLAUDE.md repo map brought up to date.
- Tone (#76): the bro's lines live in `ya_bro/tone.py` and are playful by default ("See?! That's not it, bro. I warned you"), plain at `humour = 0`; **Why?** after a wrong key explains the mistake (what the screen shows vs what was needed, capped to 24 characters of screen text) and the explanation goes away when you undo it.
- Wrong action noticed (#74): when a step watches an element's text and it changes to something else and settles, the bro says what it expected and offers Undo or Next. `Perception.read_text` added. Tested on the real Calculator (5 instead of 7, clear, then 7).
- Steps verify from element text (#72): `expect = {role = "text", text = "42"}` reads the element's AT-SPI text, and the step advances by itself once the screen shows it. Next on a step that is not done asks first ("I don't see that yet") and skips only on a second press; a step that already looks done waits for Next. The Calculator example now verifies 7, 7×, 7×6 and 42 from the display, and the README GIF was re-recorded. `Perception.find` takes an optional `text`.
- The bubble no longer leaves the screen (#69): it goes below the target, above it when there is no room, and is clamped inside the monitor (avatar included); `Overlay1.GetState` reports the placed `bubble` rectangle. Tested at the four corners, bottom edge and middle. Reload the extension to get it (`broctl setup` copies it again, then disable and enable it).
- Live trial fixes (#68): a log field named `event` crashed `broctl show` on the first button press (logging can no longer stop the loop); plans take `extents_offset` because GNOME Calculator reports key rectangles 12 px right and down (finding S9); `examples/plans/calculator.toml` and a reference GIF (`docs/assets/show-me-calculator.gif`, `scripts/dev/record_demo.py`).
- `broctl show <plan.toml>`: the Show-me step loop (#66, refs #5). A scripted TOML plan is walked one step at a time: the ring and bubble point at the real element (AT-SPI window extents plus the extension's window origin, ADR-0004), the loop waits for the user, checks the screen (an expected element appears or disappears), then advances. Bubble buttons: Next, Repeat, Why, Stop (also Super+Shift+Esc). A missing target gets a bubble only, never a guessed ring; losing focus or scope hides the overlay. The perceiver only walks apps that own an allowed window. Verified in the headless shell by clicking where the ring points. No LLM brain yet (#5).
- `broctl targets list|allow|revoke` and a loopback token endpoint (127.0.0.1:47800): `broctl point` / `scope watch` hand the extension a per-run token, issued only to a page on an allowed origin (CORS plus `X-Scope-Token` header, Host check). The page puts it in `document.title`, so only that tab is in scope. `scripts/dev/token_page.py` is a demo page. CLI commands are stored but not enforced until the shell hook (#21). Verified end to end with a real Chrome and workbench's opt-in title token (workbench#984); the header is `X-Scope-Token`.
- `broctl apps available` lists installed apps (id, name, window class) from `.desktop` files (#47). ADR-0025 (proposed): pack-scoped targets so a tool with a web UI and a CLI, like workbench, can be allowed without exposing the whole browser or every shell.
- `broctl`, a kubectl-style control CLI (`broctl <noun> <verb>`, ADR-0024, #45): `version`, `doctor`, `setup`, `apps list|allow|revoke`. It replaces the `ya-bro` management commands; `ya-bro` stays the product and agent name.
- Per-app scoping (#43): the Shell extension is default-deny. Only windows of apps in its `allowed-apps` setting are listed, tracked, announced or measured; the title and pointer calls are refused otherwise. `broctl setup` asks which one app to allow (and writes `apps/<id>.toml`), and `broctl doctor` reports the allowlist. The accessibility setting itself stays system-wide (GNOME has no per-app switch).
- `broctl doctor` (session, accessibility bus, extension state, API key presence) and consent-gated `broctl setup` (accessibility setting, Shell extension install and enable) (#17).
- Config loader (`ya_bro.config`, `config.toml` plus per-app overrides, warns on unknown keys) and content-free typed JSONL log API (`ya_bro.logs`) per ADR-0017 (#36).
- Working rules for agents and contributors in CLAUDE.md (watch background jobs, harness safety).
- Spike S1 (#15, go/no-go still open): GNOME Shell extension prototype in `extension/` (`Bridge1`, `Overlay1`, peer checks, dead-man switch, stop key, Bézier pointer flight), isolated headless-shell harness `scripts/dev/headless-shell.sh` (private bus, display, runtime dir, Xwayland, camera-masked WirePlumber), contract test (`pytest -m gnome`) and a measurement suite (`pytest -m gnome_measure`) with raw JSON and findings in `docs/research/spikes/`. Measured per-toolkit window origins (GTK4/libadwaita frame, GTK3 buffer). ADR-0023 corrected (`GetMonitors` signature, `GetState`, `layout_mode`); stop key needs a stage `captured-event` fallback because Mutter dropped the binding in about half of test sessions (fixed: 10/10 headless, 5/5 nested). `YB_DEVKIT=1` runs the harness in a nested `mutter-devkit` window on the real desktop.
- Project skeleton (#16): `src/` layout, uv/ruff/pytest config, 12 provisional interface Protocols with in-memory fakes, IPC name helper, XDG `dirs`, `ya-bro --version`, GTK4 AT-SPI fixture test, `scripts/check.sh`, CI workflow drafted at `docs/ci/ci.yml` (not active: the maintainer's token lacks `workflow` scope, so it must be copied to `.github/workflows/` by hand; never run), `docs/PROGRESS.md`, `docs/DEVELOPMENT.md`.
- Concept sketch (`docs/assets/ya-bro-concept.png` and SVG source).
- Architecture ADR set (0002–0023), ADR index with ranked risks and MVP build plan, and research docs on AI tools, non-AI tools and the Linux platform.
- Platform re-plan: GNOME 50 Wayland is the reference platform (maintainer decision), KWin Wayland moves to v0.2, X11 becomes CI-only. ADR-0023 designs the GNOME Shell extension bridge + overlay, and ADR-0022 re-orders the spikes so that extension is S1.
- ADR-0001: Python 3.12 + GTK4 chosen as implementation stack.
- README title no longer has an emoji.
- Spec: proactive "you stuck?" mode, global core + app packs (workbench first), monitoring privacy rules.
- Initial repo scaffold: `CLAUDE.md`, `SPEC.md`, issue/PR templates, prior-art survey.

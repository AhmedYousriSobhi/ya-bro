## [Unreleased]

### Added
- Do-it text entry (#27, ADR-0009 §4): a plan step can carry `text = "..."` (one printable line, up to 200 characters, needs a `target`). With `--do-it` the bubble shows the exact text and asks first (R2); Bro then enters it through AT-SPI `EditableText` (no key injection, no clipboard) and checks it reads back exactly. It refuses, and hands the step back to you, for a password field, a pack-declared secret, secret-shaped text (the same patterns as `redact`), a field that is not editable, and a field that already has text. New: `Step.text`, `plans` validation, policy R2 floor and secret check, persona moment `act_type_confirm` (English and Arabic), `AtspiActuator._type`. Tested with four loop tests on fakes, plan and policy tests, and a real GTK4 app in the isolated shell (fill an empty field; an overwrite and a password field refused); removing the empty-field guard fails it. **Not built / not verified:** the portal + libei path, rich text and multi-line, an Arabic string in a real app, the live desktop.
- Terminal companion (#115, ADR-0029): `broctl ask GOAL --pack ID` now puts Bro's bubble beside an allowed terminal (or in its own window), showing each step's command in a code box with **Copy** (clipboard) and **Write it** (the command appears at your bash prompt, never run; you press Enter). Write it asks the terminal for a status report and the hook puts the line at an empty prompt: no key injection, refused when text is at the prompt, when something is running, for destructive commands, or when more than one terminal is idle. When the hook sees the command finish the plan moves on by itself (a failure is reported and waits). New: plan step `command`, `ya_bro.shell_command`, `terminal_write`, `command_watch`, hook idle marker and binding, extension `snippet` and `copy`/`write` buttons (**reload the extension: `broctl load` or log in again**), persona moments `copied`, `written`, `cmd_failed`; the companion runs in the background so the prompt returns. Tested in real bash on a pty (7 tests, two mutations) and in a real VTE terminal in the isolated shell (bubble, Copy then paste, Write it, Enter, advance). **Not built:** zsh and fish, scoping by terminal title instead of allowing the whole terminal app (ADR-0029), Ptyxis and other terminals unverified, Do-it for terminals beyond filling the prompt.
- Terminal companion scoped by a title token (#117, ADR-0029 §8): the bubble hovers beside your terminal **without** `broctl apps allow <terminal>`. For the length of a run core makes a random token, the bash hook puts it in the terminal title (OSC 2) at each prompt, and the extension reports that window only while the token is in its title (the existing `SetScopeTokens`, ADR-0025); core nudges the one idle terminal so the title shows at once. Nothing is reported once the run ends. Tested in real bash on a pty (title set, none without a token file, a malformed token file never echoed, gone when core stops, the nudge inserts nothing) and on a real frame in the isolated shell with no app allowed (a run with the token write removed fails it). **Not built / not verified:** Ptyxis honouring OSC 2 for the window title, zsh and fish.

New: plan step `command`, `ya_bro.shell_command`, `terminal_write`, `command_watch`, hook idle marker and binding, extension `snippet` and `copy`/`write` buttons (**reload the extension: `broctl load` or log in again**), persona moments `copied`, `written`, `cmd_failed`; the companion runs in the background so the prompt returns. Tested in real bash on a pty (7 tests, two mutations) and in a real VTE terminal in the isolated shell (bubble, Copy then paste, Write it, Enter, advance). **Not built:** zsh and fish, Ptyxis and other terminals unverified, Do-it for terminals beyond filling the prompt.
- `broctl ask GOAL --pack ID` (#22): walk through a pack's task in a plain window with no extension, no allowed app and no screen reading, for tools that are a terminal or a web page (workbench). The pack's steps appear one at a time; you do each and press Next. Tested on a real frame (three real Next clicks finish the workbench `start-cluster` task). New guide `docs/guides/workbench.md`: what works on workbench today (task walk-through, `benchctl` hook and stuck offers, web page scoped to its tab) and what does not (pointing at web elements, Do-it on terminals, the offer's Yes does not yet explain an error code).
- Ask window (#3): `broctl ask` with no goal opens a small GTK4 window with one text field (Go or Enter sends, Cancel, Esc or closing cancels, an empty field counts as cancel); what you type then goes through the same pack-then-Claude planning as `broctl ask GOAL`. Tested on a real frame in the isolated shell (a real click on Go returns the text; breaking Go fails the test). **Not built:** a hotkey to open it, voice input, history, and it is not shown on KDE or without the extension (the planning step still needs the bridge for scope).
- Docked overlay (#3, ADR-0006, first part): `platform/docked_overlay.py`, the bubble as a small GTK4 window (narration, Next/Repeat/Why?/Stop buttons, Esc or closing the window is Stop, RTL text direction) with no ring and no pointer, for when the Shell extension is missing. `broctl show PLAN --docked` uses it. Found by the real test: under the GLib asyncio loop GTK's Wayland source is not serviced while the loop sleeps (the window stays 0 x 0 and clicks miss), so the overlay iterates the default context itself. Tested on a real frame in the isolated shell (real clicks on Why? and Stop arrive as events; swapping the button's event fails the test). **Not built:** automatic fallback when the extension is absent (`--docked` is chosen by hand; `broctl show` still needs the bridge for window scope), the GTK ask window, a layer-shell overlay for KWin, and a check that it does not steal focus from the app being shown.
- `YB_UNSAFE=1` for `scripts/dev/headless-shell.sh` starts the isolated shell with `--unsafe-mode`, so a test can call `org.gnome.Shell.Introspect.GetWindows` to learn an app's real window id (used to find VS Code's, `com.microsoft.VSCode`).
- Spike S2 (#2, first part): `tests/fixtures/shell_atspi_coverage.py` counts, per role, the named and on-screen elements in a real app's accessibility tree, and `docs/research/spikes/S2-atspi-coverage.md` reports LibreOffice Writer (VS Code, Firefox, GIMP, Inkscape and KDE Settings not measured, with reasons).
- Do-it on GNOME (#27, ADR-0009, first part): `broctl show PLAN --do-it` has Bro press the controls itself through AT-SPI actions (no pointer injection, no portal consent), one step at a time and visibly: it narrates, flies the pointer to the control, waits (`act_pause`), presses, then checks the step's `expect` (`verify` seconds). It only presses a control it found with High confidence and exactly one match, never in a password field, and only when `[do_it] allowed = true` for the app. R2 steps ask first ("press it for you? OK") with Next and Stop; R3 steps, dangerous names, a missing or doubtful control, and two failed presses (one retry) go back to Show-me: Bro points, you press. Stop (button or key) before or during a press halts at once and calls `Actuator.abort`. New: `AtspiActuator`, `StepLoop(actuator=)`, `Timing.act_pause` and `verify`, persona moments `act_confirm` and `act_failed` (English and Arabic drafts). Tested with 12 loop tests on fakes and a real Calculator run in the isolated shell (7 × 6 = 42 pressed with no injected click; an actuator that cannot press fails it). **Not built:** text entry, the RemoteDesktop portal + libei path (drags, canvas, apps with weak AT-SPI actions; spike S7), the "want me to undo that?" offer, slow/normal/brisk pacing, and the S7 coverage run across GIMP, LibreOffice, Settings and Firefox.

## [0.2.0] - 2026-11-23
Second pre-alpha release. Bro can now take plain words, guard your privacy, and offer help when you seem stuck. The agent is called **Bro**; "Ya" is the call that summons it.

**Highlights:** `broctl ask` (a pack task, else Claude plans it, with a preview and re-planning), consent and a kill switch (`broctl sent|forget|panic|consent`), the API key in your keyring (`broctl key`), the "you stuck, bro?" detector with an offer bubble and AT-SPI sources, app knowledge packs, a bash hook, a persona with Arabic drafts, a pointing eval, a licence gate, and a new look for the bro. **Not verified:** the Claude brain has never run against the live Anthropic API.

### Added
- AT-SPI sources and the offer bubble now work together: `broctl struggle watch` runs one watcher (under the system python3) fed by shell, idle and AT-SPI and shows the bubble; `--print-only` prints the same offers instead. A real test (two real GTK3 error dialogs, the bubble on a real frame, a real click on No, the state file) found that the watcher was refused window lists ("Caller not allowed": the extension reserves them for Core or Perceiver and the watcher held neither); both watchers now own the read-only Perceiver name for their run.
- Struggle offer bubble (#9, ADR-0010 §4): when the detector makes an offer, Bro asks "you stuck, bro?" in a bubble (persona moments `offer_stuck`, `offer_declined`, `back_off_long`, English and Arabic) with three buttons: Yes (the bro greets and the `accepted` hand-over fires), No, and Not for this app. Each answer goes to `Detector.answer`, so the real back-off runs (a "no" silences that signal, two in a row silence the app for 30 minutes, "not for this app" opts it out); an unanswered bubble fades after 20 s and counts as a soft "no"; the stop key counts as a "no". It never interrupts a step loop (the watcher holds the Core bus name only while a bubble is up and stays quiet when `broctl show` owns it) and there is one pending offer at a time. New: `ya_bro.offers`, `platform/gnome_offers.py`, `StruggleHost(present=, busy=)`, `Detector.withdraw` and `is_quiet`; `broctl struggle watch` now draws the bubble (`--print-only` keeps the old behaviour); `broctl panic` also stops the watcher. The extension keeps its fixed button list; its button row gained a 6 px gap. Tested on real frames in the isolated shell: a real pointer click on each button changes the detector's state, a mutation (Yes and No swapped) fails the test, and the real watcher process is quiet while Core is owned, then offers and is answered.
- API key storage (#5, ADR-0008 §9, ADR-0014): `broctl key set|status|clear` keep the Anthropic key in the system keyring (Secret Service via libsecret) instead of a plain file. `set` asks with a hidden prompt (one line from a pipe when stdin is not a terminal), never takes the key as an argument, checks only the shape (printable, 20 to 400 characters; a different prefix is a note, not an error) and never echoes it. Lookup order for `ANTHROPIC_API_KEY`: environment, keyring, `.env` (`brain.load_key`, `keystore.find`); `status` names the winning source and any second copy, never the value. `broctl doctor` shows present (with the source) or missing; `broctl forget --everything` lists and, after the usual yes, removes the stored key. No new dependency: the core talks to a small helper (`platform/secret_service.py`) run by the system python3, which has PyGObject and libsecret; the key travels over a pipe, never argv or environment. Tested with a fake store (25 tests, including one that greps logs, the sent ledger, config, cache, output and a traceback for the key) and against a real gnome-keyring-daemon in a private session bus, private HOME and a bwrap namespace that hides the user's own keyring (`pytest -m keyring`, in `scripts/check.sh`; skips with a reason when bwrap, dbus-run-session or gnome-keyring-daemon are missing).
- AT-SPI struggle sources (#9, ADR-0010, part of): menu thrash, dialog bounce, error dialogs (GTK3 `alert` role), undo bursts and typing as content-free events from the apps you allowed and enabled for struggle. `UiEventSource` interface, a gi-free translator (`ya_bro.ui_events`) built from what GTK4 on GNOME 50 really sends, and `platform/gnome_atspi_events.py`. `broctl struggle watch` runs it (system python3) alongside the shell and idle sources, and now applies packs' `signals.toml`. Real test on GTK4 and GTK3 fixture apps in the isolated shell, with a mutation run that must fail; six recorded AT-SPI scenarios in `evals/struggle/` (eval: 68 scenarios, precision 97%, recall 70%). Known gaps in ADR-0010 and `docs/PROGRESS.md`.
- Claude brain (#5, ADR-0008): `ya_bro.brain.ClaudeBrain` turns plain words into a plan with one call to the Messages API and a strict `propose_plan` tool, over the standard library (no SDK). In order: the consent gate and a key check (nothing is sent otherwise), redaction of control names and fencing of the screen as an untrusted `<observation>` (markup stripped, password fields dropped, bounded), the sent ledger (question, elements, pack: kinds and sizes), a per-task call budget (default 30, one retry on 429/529), then strict validation of the answer: at most 12 steps, malformed or missing-risk steps count as the worst case, local policy can only raise a step's risk, and the persona's safety filter drops links, commands and banned topics from narration (the intent stands in, else nothing is shown). The frozen prompt follows ADR-0008 §5 (rules and tone guide, then pack knowledge with the cache breakpoint). `FallbackBrain` answers from a pack task first with no model call. `broctl ask GOAL [--app] [--dry]`; `[brain] model` and `max_calls` in config; the model address must be https (http only for localhost, via `ANTHROPIC_BASE_URL`). Tested on a local stand-in server over real HTTP (31 tests) and on the real GNOME Calculator in the isolated shell (the model is told the real controls, its targets resolve to real controls, a pack task makes no request). Follow-ups in the same PR: a plan the model wrote is first shown as a preview bubble (step count and the first step, Next to start, Stop to cancel; pack and file plans skip it); when a step's control is missing for 4 s the loop asks the model for the remaining steps (`ClaudeBrain.revise`, told what was already shown and which control is gone, up to 2 times per task, each new step through the same validation and policy; a pack's own steps are never rewritten); token use is summed and printed after the run (`2 model call(s): 900 in, 120 out, 75% of the input from cache`). Two new persona moments (`plan_preview`, `replanning`, English and Arabic drafts). Tested with 16 more unit tests, and on the real Calculator: preview, a click on Next, a missing control, the revised request, and the ring landing on the real 7 key (disabling the trigger fails it). **Not yet run against the live Anthropic API**: no key was available; a `live` test exists for that.
- Consent UX and kill switch (#25, ADR-0014 §2, §3, §6, §7): `broctl setup` opens with a first-run screen (what Bro reads, keeps and would send; sending and screenshots default to no) recorded in `consent.toml`, and `privacy.may_send()` is the gate every future request passes; `broctl consent show|revoke`; `broctl sent` reads a content-free ledger of requests (kind, bytes, destination; free text is refused); `broctl forget [--everything] [--yes]` previews, asks, then deletes logs, offers, cache and the spool (and with `--everything` also targets, allowed-app records, consent and the `.bashrc` hook lines); `broctl panic` SIGKILLs every running `broctl show|point|scope watch|struggle watch|shell watch` and the stand-in cores (never itself or its shell, never a `struggle status`), clears the spool and turns proactive mode off; the overlay then hides by the existing dead-man switch. The overlay draws state dots under the bro (blue watching, green listening, red sending, orange acting) from a fixed list, via `ShowStep indicators` or `SetIndicators`, reported by `GetState`; the GNOME adapter shows "watching" whenever it is up. Logs older than 7 days can be pruned (`privacy.prune_logs`). Tests no longer touch your real config, state or cache (`tests/conftest.py`). Tested on real processes (a SIGSTOPped core is killed in under 0.5 s) and real frames (each dot colour; a mutation of the stylesheet fails the test).
- Naming: the agent is called **Bro**; "Ya" is only the call that summons it, and Ya-Bro stays the project and repo name. README, user guide, setup and CLI text, the persona and SPEC now say "Bro" where they said "Ya-Bro" for the agent.
- Persona (#23, ADR-0013): `ya_bro.persona` with a data-first definition (14 moments with humour ceilings, 79 English and 79 Egyptian Arabic lines, a tone guide for the Brain) and the rules in code: no humour in errors, uncertainty, recovery or risky and private steps, one level less when you seem frustrated, a "less chatty" mode, "bro" once per task, no repeats, bidi-safe UI names, the bro follows your language, and a safety filter for generated lines. New config keys `language` and `less_chatty`; the overlay now gets `dir = rtl` for Arabic. A risky step gets a plain "this one is yours to press" line, the teasing face needs humour, and the can't-find and hedge lines are no longer playful. `broctl persona say|list|lint|style`. The Arabic lines are drafts that need native review.
- The bro has a (provisional) look (#96, ADR-0028): an identity study with five original candidates, a ranking and artwork (`docs/design/BRO_IDENTITY.md`; the maintainer rejected Yaya and Fenn, their artwork is removed); the Shell extension now draws the bro from six SVG moods (`extension/assets/bro/`) instead of the amber "Ya" circle, `ShowStep` takes a `mood`, the step loop shows pointing, thinking, teasing and idle, and a plan ends with a happy "all done" bubble (1.5 s in `broctl show`). The README is restructured with the bro and a new animated demo GIF (560 x 640, 1.3 MB, about 29 s): recorded from the real overlay at 2×, a camera that centres the Calculator and zooms in and out onto the bro's bubble so its words are readable, a title card and an end card that pop in. `scripts/dev/record_demo.py` makes it.
- Licence compliance gate (#26, ADR-0020): `scripts/check_licences.py` (in `scripts/check.sh` and the CI draft) reads the dependency closure from `uv.lock` and fails on an unlisted package, strong copyleft in anything that ships, a forbidden package (Piper, espeak-ng, ydotool, dogtail), installed metadata that disagrees with the policy `docs/licences.toml`, a copyleft import under `src/`, or a project or pack that is not MIT. `docs/LICENCES.md` explains it and lists the closure. Packs gained an optional `license` field; shipped packs say MIT and `broctl pack list` shows it.
- Struggle replay eval (#24, ADR-0010, ADR-0016): `broctl eval struggle [-v] [--sensitivity N] [--sweep]` replays `evals/struggle/` (62 labelled event streams: 54 scripted, 8 recorded from a real bash with the hook) through the detector on a fake clock and scores precision, recall, time to offer, false offers per hour of calm and the back-off rules, with the ADR's gates (exit 1 below them). Default sensitivity: precision 97%, recall 74%, median 20 s, 0.31 false offers per hour. Tests show that breaking the back-off, or making the detector jumpy or deaf, fails the eval. `scripts/dev/make_struggle_corpus.py` builds the scripted set; `python -m tests.record_struggle` records the real-bash set.
- Struggle detector (#9, ADR-0010): `ya_bro.struggle` takes content-free observations and offers help at a breakpoint when a decaying score passes the threshold, with the whole back-off policy (one pending offer, 2 min cooldown, 3 an hour and 10 a day, a "no" silences that signal until the context changes, two in a row silence the app for 30 min, three in a week halve the weight, "not for this app", opt-in per app, sensitivity 1 to 4). Sources built: failing commands from the shell hook and idle from GNOME's IdleMonitor (`StruggleHost`); packs tune it with `signals.toml` (workbench ships one). `broctl struggle status|on|off|enable|disable|sensitivity|watch`. Off for every app until you enable it. Tested with real bash plus the real spool and with real Mutter idle in the isolated shell. The AT-SPI sources (menus, dialogs, undo), the offer bubble and the learned gate are not built.
- Shell hook and terminal reading (#21, ADR-0021, ADR-0025): `shell/ya-bro.bash` records, for commands you allowed with `broctl targets allow --command`, only the name, exit code, duration and tty when each finishes (no arguments, no output; nothing for other commands, nothing at all while Ya-Bro is not running); `ya_bro.shell_spool` is core's side (private runtime dir, allowlist file, validated reads); `ya_bro.terminal` reads a VTE terminal's text over AT-SPI after you accept help (redacted, bounded) and finds the pack's fix-it for a `CODE: message | fix: COMMAND` line; `broctl hook install|uninstall|print|status` (edits `~/.bashrc` only after a yes) and `broctl shell watch`. Bash only. Tested in a real interactive bash (100 commands, under 5 ms per command, existing DEBUG trap and `PROMPT_COMMAND` kept) and on a real VTE terminal in the isolated shell.
- Pointing eval harness (#19, ADR-0007, ADR-0016): `ya_bro.grounding` turns an AT-SPI element list into a pointing with a confidence tier (high: same name after normalising and a 0.3 margin; medium: close or tied, shown with a hedge, "I think it's this one"; none), skips a ring whose centre is outside the focused window (ADR-0004), and the step loop now uses it (it used to take the first match). `AtspiPerception.find` returns each element's own name. `broctl eval pointing [-v] [--dir]` scores labelled snapshots in `evals/pointing/` (pointed-correct against the 80% gate, confidently-wrong against 2%, blocking release above 5%, medium precision, latency per tier, misses by kind, locale and app; exit 1 below the gate). Ships 300 **synthetic** cases (6 made-up apps, English and Arabic; `scripts/dev/make_pointing_corpus.py`) and 219 cases from **recorded real trees** of GNOME Calculator, Files and Settings (`tests/fixtures/shell_pointing.py`). Real-app checks in the isolated headless shell: all 10 Calculator digit keys pointed at by name and clicked in the ring type that digit, 7 × 6 = 42 by pointing at each key, Settings and Files rows open their page when clicked.
- Local policy engine and redaction (#20, ADR-0014 §4): `LocalPolicy` takes the highest of the step's risk, the pack's risk for that element and local heuristics (a bilingual whole-word deny-list on the element name, destructive-command patterns, password fields and pack-marked secrets). Show-me marks R3 steps as the user's own click; Do-it (still off) shows R3 and never acts, confirms R2, and never touches a secret field. Packs declare element risk and secrets with `[[element]]` (ADR-0027). `ya_bro.redact` replaces private keys, JWTs, AWS, GitHub, Slack and API keys, bearer tokens, `password=`-style values and URL passwords with `[redacted:kind]`; the bro's echoed screen text is redacted before it is cut. Tests: 177 element names (EN and AR) in both modes (354 decisions) and 50 injected texts that change no decision.
- App knowledge pack format v1 and loader (#8, ADR-0027): `packs/<id>/pack.toml` + `knowledge.md` + `tasks/*.toml`, exact app matchers, validated at load, broken packs skipped; `broctl pack list|check`; first pack `packs/gnome-calculator`.
- Workbench pack (#22): `packs/workbench` for `benchctl` (vocabulary, rules and common mistakes from AGENTS.md, four terminal tasks, 32 error-code explanations in `fixits.toml`). Pack format gained `fixits.toml` (ADR-0027); a suggested command must be one of the pack's own.

## [0.1.0] - 2026-11-22
First tagged release (pre-alpha): the scripted Show-me loop on GNOME Wayland, with hand-written plans. No LLM brain, voice or Do-it mode yet.

### Added
- Fixed the ring tinting the window interior (its glow filled the box; now a plain 4 px border, pixel-tested) and `broctl point` now draws only on a focused allowed window and tells you which window to click otherwise (#59).
- `broctl load`: loads the Ya-Bro extension into the running Shell without logging out. It copies a one-line snippet to the clipboard and walks through Alt+F2, `lg`, paste; verified in the isolated headless shell with injected keys (#57).
- Measured that a locally installed Shell extension cannot be loaded without a Shell restart (ADR-0023 §9).
- `broctl point` draws the Ya-Bro ring and a bubble on your allowed app's window and follows it (Stop button or Super+Shift+Esc hides it); `broctl scope watch` prints allowed windows entering and leaving scope. Both stand in for core until it exists, run under the system python3 with PyGObject, and were tested in the isolated headless shell only (#53).
- `broctl setup` shows a searchable list of installed apps (type a word, pick a number) instead of asking for a raw app id; it stores the window class when the app has one (#51).
- Spike S8 (#47): the Shell extension can scope a window by a secret title token pushed by core (`Bridge1.SetScopeTokens`, core only, memory only; the window leaves scope when its title changes), and windows re-evaluate when `allowed-apps` changes. Verified with a stand-in window and a real browser (Chrome for Testing; `pytest -m gnome_measure`). Findings in `docs/research/spikes/S8-active-tab-scope.md`.
- README demo GIF, narrated (#82, #84): native resolution with one shared 256-colour palette (86 KB, 606 x 798), a narrator caption track, a title card, and the funny parts: the wrong-key tease, **Why?** explaining the mistake, the forgiveness; `scripts/dev/record_demo.py` produces it.
- Repository polish (#80): professional README (badges, demo, status table, quick start, safety, command table), a step-by-step [user guide](docs/guides/getting-started.md), MIT `LICENSE` (the maintainer chose MIT only; ADR-0020 updated, `pyproject.toml` metadata), GitHub topics and description, a neutral [how-it-works diagram](docs/assets/how-it-works.svg) in place of the mascot concept sketch (removed), and a Show-me GIF recorded without the placeholder avatar (`ShowStep` takes `avatar = false`).
- ADR-0026 records the Show-me step loop decisions (#78); README status, ADR-0024 command list, SPEC (as-built loop), milestone table and the CLAUDE.md repo map brought up to date.
- Tone (#76): the bro's lines live in `ya_bro/tone.py` and are playful by default ("See?! That's not it, bro. I warned you"), plain at `humour = 0`; **Why?** after a wrong key explains the mistake (what the screen shows vs what was needed, capped to 24 characters of screen text) and the explanation goes away when you undo it.
- Wrong action noticed (#74): when a step watches an element's text and it changes to something else and settles, the bro says what it expected and offers Undo or Next. `Perception.read_text` added. Tested on the real Calculator (5 instead of 7, clear, then 7).
- Steps verify from element text (#72): `expect = {role = "text", text = "42"}` reads the element's AT-SPI text, and the step advances by itself once the screen shows it. Next on a step that is not done asks first ("I don't see that yet") and skips only on a second press; a step that already looks done waits for Next. The Calculator example now verifies 7, 7×, 7×6 and 42 from the display, and the README GIF was re-recorded. `Perception.find` takes an optional `text`.
- The bubble no longer leaves the screen (#69): it goes below the target, above it when there is no room, and is clamped inside the monitor (avatar included); `Overlay1.GetState` reports the placed `bubble` rectangle. Tested at the four corners, bottom edge and middle. Reload the extension to get it (`broctl setup` copies it again, then disable and enable it).
- Live trial fixes (#68): a log field named `event` crashed `broctl show` on the first button press (logging can no longer stop the loop); plans take `extents_offset` because GNOME Calculator reports key rectangles 12 px right and down (finding S9); `examples/plans/calculator.toml` and a reference GIF (`docs/assets/show-me-calculator.gif`, `scripts/dev/record_demo.py`).
- `broctl show <plan.toml>`: the Show-me step loop (#66, refs #5). A scripted TOML plan is walked one step at a time: the ring and bubble point at the real element (AT-SPI window extents plus the extension's window origin, ADR-0004), the loop waits for the user, checks the screen (an expected element appears or disappears), then advances. Bubble buttons: Next, Repeat, Why, Stop (also Super+Shift+Esc). A missing target gets a bubble only, never a guessed ring; losing focus or scope hides the overlay. The perceiver only walks apps that own an allowed window. Verified in the headless shell by clicking where the ring points. No LLM brain yet (#5).
- `broctl targets list|allow|revoke` and a loopback token endpoint (127.0.0.1:47800): `broctl point` / `scope watch` hand the extension a per-run token, issued only to a page on an allowed origin (CORS plus `X-Scope-Token` header, Host check).
